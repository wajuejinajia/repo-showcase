repo-showcase — source-backed project websites

Agent Skill that turns a code repository into a style-led static showcase. Claims stay tied to repository sources; output is dependency-free HTML suitable for a homepage or GitHub Pages.

[AGENT SKILL] [STATIC HTML] [MIT] [BASH + PYTHON 3]
[ install ] [ github ]

┌── [SECTION 01] FEATURES ──┐

────────────────────────────────────────

  • source-backed Every public claim maps to a repository file and line, or is omitted.
  • portable output Inline CSS/JS, system fonts, local assets — no build step or CDN by default.
  • 8 visual systems Styles define typography, layout, motion, and constraints — not only colors.
  • honest checks validate-site.py enforces structure, size, placeholders, and local resources.
  • optional multi-page showcase-docs and showcase-guide-demo add static Docs, Guide, and/or Demo routes.
  • explicit publishing Deployment and remote changes happen only when requested.

Runtime for deterministic checks: Bash and Python 3. No Node modules required.

┌── [SECTION 04] USE ──┐

────────────────────────────────────────

$ cat <<'PROMPT'

Build a project showcase site for this repository. Recommend a style first.

Create a project homepage in tech-futuristic style and verify it locally. Do not deploy it.

Use repo-showcase in showcase-guide-demo mode. Create the homepage, a guide
quick-start page, and a demo page from the repository's real examples.

$ # workflow

  1. bash scripts/analyze-repo.sh <target-repo> → .repo-showcase/facts.json
  2. Choose a style from styles/*.md; start from templates/base.html
  3. Write site/index.html (inline CSS/JS, system fonts)
  4. python3 scripts/validate-site.py site

┌── [SECTION 05] VERIFY ──┐

────────────────────────────────────────

$ python3 scripts/validate-site.py site
$ python3 scripts/validate-site.py site --all
$ python3 -m http.server 8000 --directory site

Smoke tests: bash tests/test_analyze_repo.sh and bash tests/test_validate_site.sh.
